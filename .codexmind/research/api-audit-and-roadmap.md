## 1. Executive Summary

NativeMods already had a **live-proven vertical slice** on real PoE **3.29.3d** under Proton (`0.1.0-poc`), and **Phase 0 (`0.2.0`)** has now resolved the foundational ABI, threading, symbol, bundle, UI/clipboard/file/network wiring, `ServerBridge` ergonomics, and showcase migration gaps.

The pre-Phase-0 audit exposed a **sharp split between what the SDK declared and what was wired in `native-shim`**, plus **three structural bottlenecks** blocking the community wishlist:

1. **Over half the `0.1.0-poc` SDK surface was simulated/managed-only on `3.29.3d`:** `ITextBox`, `ICheckBox`, `IClipboardService`, `IUiControl` geometry/lifecycle, `INetChannel.SendRaw`/`OnRaw`, `IOpcodeRegistry` (`0x02FC+`), `IFileOverlayService.ReadStockGameFile`/`Invalidate` — **now wired in Phase 0 (`0.2.0`)** via C ABI `560 B` / `69` slots (`122` symbols in `3.29.3d.json`). Remaining engine surfaces (`IWorldService`, `IStatsService`, `IGealBuiltinRegistry`/`IScriptService` native VM wiring, `IRulesetRegistry` native creator table, `IGameLifecycle.AreaEntered`/`AreaLeft`, `IContentRegistry.DeclareDatRow`) are scheduled for **Phases 2 and 4**.
2. **Zero stock-UI, input, hover, or item-filter APIs exist yet:** Almost every gameplay screen in PoE 3.29 (Inventory, Stash, Map Stash, Blight Stash, Passive Tree, Vendor, Ground Loot Labels) is a **C++-constructed `UI::Control` tree**, not a `.ui` file. Without **Stock Panel Attachment + Screen State** (Phase 1), **Input/Hotkey Interception** (Phase 1), **Hovered-Item Inspection** (Phase 1), and a **Client Item-Filter Visibility Bridge** (Phase 2), mods cannot add native buttons to Stash/Inventory, cannot detect `CTRL+SHIFT+RMB`, and cannot build filter-aware Loot Magnets (because PoE item filters are **100% client-side**).
3. **No multi-mod `.datc64` merging or row-ID negotiation yet (Phase 3):** Content mods currently ship pre-patched `.datc64` binaries in `replaces` with fixed 3.29.3d row indices (`5461`, `8557`). Composable `.datpatch.json` delta-merging (`DatPatchMerger`) + handshake `content-row-map.json` synchronization will land in **Phase 3**.

> **High-Leverage Insight:** Just **4 foundational API pillars** — (1) Completing core UI (`TextBox`/`CheckBox`/dynamic children/`Clipboard`, **done in Phase 0**), (2) Stock Panel Attachment + Screen/Tab State (Phase 1), (3) Input/Hotkey + Hovered-Item Inspection (Phase 1), and (4) World Entities + Client Item-Filter Bridge (Phase 2) — unlock **~80% of the entire community wishlist**.

## 4. Locked-In Architectural Decisions & Phased Execution Plan

### Locked-In Decisions
- **Execution Order:** **Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5**.
- **Target Client Build:** Build & live-verify on **`3.29.3d`** first; batch-port data/vtable RVAs to **`3.29.3c`** in Phase 5.
- **Plugin & Hook Model:** Managed C# SDK + multi-mod x64 hook chaining (`HookEngine` `TargetChain`).
- **Stock UI Conflict Resolution:** Managed auto-flow toolbar slots — **in-game** (`InventoryToolbar`, `StashHeader`, `StashFooter`, `MapTabBar`, `BlightTabBar`, `PassiveTreeHeader`, `HudTopRight`) and **pre-game** (`LeagueCardModes` auto-reapplied on `LeagueOverlay::Fill`, `CreateCharacterBar`) — plus native stock-tree `Find`/enumeration on `IUiService` and raw `AttachToControl` escape hatch.
- **Input & Keybind Resolution:** Centralized Keybind Registry (`Mods/Client/keybinds.json`) + conflict warnings + low-level suppressible key/mouse hooks.
- **Authoring DX:** Tier 1 (single `.cs` Roslyn server script via `ServerBridge`) and Tier 2 (`<id>.Client.dll` against `LocalExile.Client.Sdk` + local NuGet + `nativemods new`).
- **Multi-Mod `.datc64` Merging:** Shared C# `DatPatchMerger` → `Mods/Client/.merged-cache/`, auto-mounted at `t=0`, with `content-row-map.json` handshake digest check.
- **`LocalExile` PR Strategy:** Grouped local feature branch `feat/nativemods-phase0-core-hooks` (Part 1 landed locally in M4; Part 2 adds `GameEvents.CharacterCreated` Auth→Gateway handoff + `IPlayerWorld` progression/gold/league-character facades + public catalog & drop-pool overlays, then one combined PR).
- **Pre-Game Character Creation Options & Auth→Gateway Handoff (Phase 1 Client + `LocalExile` Core PR Part 2):** Enable opt-in character-creation mods (such as "Skip Campaign" under HC/SSF/Ruthless) to configure a brand-new character **before** its first area assignment so it spawns cleanly in its target town/level with zero Twilight Strand flash, zero double loading screen, and zero starter-kit leakage—without hosting `ServerMods` inside `GameServer.Auth` or inventing new Login TCP opcodes.
  - *Client (`NativeMods` Phase 1):*
    - Extend `IScreensService` with `PreGameScreen` state tracking (`Login`, `SelectCharacter`, `CreateCharacter`, `LeagueOverlay`, `InGame`) and managed pre-game slots: `ScreenSlot.LeagueCardModes` (auto-reinjected into each `0xdc35` card's mode `StackLayout` whenever `LeagueOverlay::Fill` `0x140cccff0` rebuilds cards, equalizing checkbox widths with HC/SSF/Ruthless and compacting height/spacing inside the `500×905` card budget) and `ScreenSlot.CreateCharacterBar` (optional mirror/badge when a Character Select league filter skips auto-opening `LeagueOverlay`).
    - Fix `IUiService.GetRootControl()` / `UiControlNode.Find()` to query native stock UI trees (`FindNativeUiChild`) and expose native child enumeration (`+0xb8`) + handle wrapping.
    - Add `IPreGameService` (`CharacterCreating(CharacterCreateContext)` hooking `0x140cf5e60` / `0x142146de0` `C→S 0x12`, and `CharacterCreated` hooking `0x140cf7fb0` `S→C 0x13`) so mods attach structured key/value options onto `CreateCharacter.S78` (e.g. `"DexDefault|nm:skip_campaign=1"`, preserving `LoginServerSession.ClassOf` prefix parsing on unmodified servers).
    - Verify & add `CreateCharacterState` (`0x140cf4ad0`, `0x140cf5e60`, `0x140cf7fb0`, `0x142146de0`) and `LeagueOverlay` (`0x140ccc160`, `0x140cccff0`, `0x140cc9370`, `0x140ccb3f0`, plus 3.29.3d vtables) to `data/addresses/3.29.3d.json` (ported to `3.29.3c.json` in Phase 5).
  - *Server (`LocalExile` Core PR Part 2):*
    - Parse structured mod options from `CreateCharacter.S78` in `LoginServerSession.Create` and notify `GameServer.Gateway` via the localhost `InstanceControl` channel (`character_created` op) **after** `accounts.CreateCharacter` and **before** `S→C 0x13` / `InstanceDirectory.AssignStart`.
    - Fire `GameEvents.CharacterCreated(CharacterCreatedContext)` in Gateway (`GameEventOwners`-tracked), exposing `(Account, CharacterId, Name, Class, League, CreationOptions)` plus writable `StartingAreaId` (sets `LastTown` before `AssignStart`, e.g. `"2_11_endgame_town"`), `StartingLevel` (updates `account_characters.level` + initial XP), and `SuppressStartKit` (pre-seeds `character_saves` with `StartWeapon = null, Tutorial = null` so `PlayerInventories.For` skips starter weapon/flasks/tutorial).
    - Expose clean public `IPlayerWorld` / progression & account facades so mods don't need direct `Modules/Core/Game` or `SqliteAccountStore` internals: `SetLevelAsync` (with Auth `set_level` sync), `SetQuestFlagsAsync` (properly stripping `UnearnedQuestFlags` so Kitava `-60%` res penalties / Pantheon upgrades apply) / `SetLeagueQuestFlagsAsync`, `GrantWaypointsAsync`, `SetRefundPointsAsync`, `AwardAscendancyAsync` (`MainAscendancy.Awards`), `GetLeagueCharacters(account, league)` (respecting exact league/SSF/HC-death isolation), and `Gold` / `AddGoldAsync(long delta)` (auto-syncing `0x02aa`).
- **Drop-Pool Injection (`LocalExile` Core PR Part 2, Phase 3):** Declarative drop-pool registration, server drop-table overlay, and `GameEvents.Drops` integration so newly added currencies, gems, equipment/flask/tincture base types, divination cards, scarabs, idols, boss items, and uniques drop naturally in the world with configurable weights, area-level gates, and monster/league source filters—owned by `GameEventOwners`, auto-cleaned on mod unload, and preserved across `/reload` without SQLite mutation or private-field reflection.
  - *Root cause solved:* Today `GameData.Open` → `WorldLoader.Load` → `GameModule.LoadData` (`new ItemDrops(...)`) all execute before `ServerMods.Start()`, and `ItemDrops` snapshots `_pools` (currency, equipment, flasks, tinctures, gems), `_cards`/`_cardWeights`, and `_scarabs`/`_scarabWeights` once in its constructor, while `GameEvents.Drops` / `DropWeights.Items` alone only scales existing entries or adds per-kill hooks (missing chests/containers, strongboxes, and boss bonuses).
  - *Design:* Pair `GameEventOwners`-owned `DropDataProvider` runtime overlays (base/currency/card/scarab/unique/boss weights, area-level min/max gates, monster-rarity/archetype & league-content filters) + `ItemCatalog` / `GemSources` / `UniqueCatalog` overlays + lazy `ItemDrops` pool rebuild on `(DropDataProvider.Default.Current, catalog.Revision, gemPoolRevision)` advances with `GameEvents.Drops` context hooks across monster kills, `ItemDrops.Container`, `StrongboxLoot`, `RollBossFirstKillBonus`, map currency mods, and `HardModeDrops`.
- **Versioning:** `0.2.0` in Phase 0; freeze `1.0.0` after Phase 3.
