## 4. Locked-In Architectural Decisions & Phased Execution Plan

### Locked-In Decisions
- **Execution Order:** **Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5**.
- **Target Client Build:** Build & live-verify on **`3.29.3d`** first; batch-port remaining `232` unverified data/vtable RVAs to **`3.29.3c`** in Phase 5.
- **Plugin & Hook Model:** Managed C# SDK + multi-mod x64 hook chaining (`HookEngine` `TargetChain`).
- **Stock UI Conflict Resolution:** Managed auto-flow toolbar slots — **7 in-game** (`InventoryToolbar`, `StashHeader`, `StashFooter`, `MapTabBar`, `BlightTabBar`, `PassiveTreeHeader`, `HudTopRight`) and **2 pre-game** (`LeagueCardModes` auto-reapplied on `LeagueOverlay::Fill`, `CreateCharacterBar`) — plus native stock-tree `Find`/enumeration on `IUiService` and raw `AttachToControl` escape hatch (**implemented in `0.3.0`**).
- **Input & Keybind Resolution:** Centralized Keybind Registry (`Mods/Client/keybinds.json`) + conflict warnings + low-level suppressible key/mouse hooks (**implemented in `0.3.0`**).
- **Authoring DX:** Tier 1 (single `.cs` Roslyn server script via `ServerBridge`, incl. `IClientPhase1Session` & `IClientPhase2Session`) and Tier 2 (`<id>.Client.dll` against `LocalExile.Client.Sdk` + local NuGet + `nativemods new`).
- **Server Mod Persistence Rule (PR `#1615` `ModHost` Reload Hazard):** `LocalExile`'s `ModHost` watches `Mods/Binaries/<id>/` and triggers a reload loop if any file is written inside a mod's binary folder. Server mods **must** persist runtime state via `IPlayerWorld.AccountData`/`CharacterData` or under `data/mods/`, never inside `Mods/Binaries/<id>/`. NativeMods' `Mods/Client/` runtime files (`.extender-state.json`, `.nativemods-ledger.json`, `keybinds.json`, Phase 3 `.merged-cache/`) are outside `ModFolders.Folder` (`Mods/Binaries`) and verified safe.
- **Phase 2 Item Filter & Enchantment Matching (PR `#1615`):**
  - `IItemFilterService` must resolve active `.filter` files from **`Documents\My Games\Path of Exile`** — PoE 3.29 always enumerates filters there and ignores `Client\config.json` subfolder redirection.
  - Native `HasEnchantment "<name>"` matches newly appended `Mods.datc64` enchantments even on **unidentified** drops (beam/color/icon/sound), enabling filter-aware custom drops without patching the client filter parser.
- **Phase 3 Multi-Mod `.datc64` Merging, Protocol IDs & Custom Stats (PR `#1615` + `re-stats-enum` `#48`):**
  - Shared C# `DatPatchMerger` → `Mods/Client/.merged-cache/`, auto-mounted at `t=0`, with `content-row-map.json` handshake digest check. Always pair client `.datc64` overlays with server runtime overlays (`ItemCatalog`/`UniqueCatalog`/`DropDataProvider`) or mod `sql/`, since Gateway never reads client bundles.
  - **Appendable vs. Closed Tables (`DualModPackageValidator`):** **18** live-verified appendable tables (`BaseItemTypes`, `ItemVisualIdentity`, `CurrencyItems`, `MtxTypes`, `MtxTypeGameSpecific`, `Pet`, `MonsterVarieties`, `NPCs`, `Chests`, `Projectiles`, `MiscObjects`, `MiscAnimated`, `HideoutDoodads`, `ExecuteGEAL`, `ClientStrings`, `Mods`, `ModType`, `BuffDefinitions`). **Closed:** `ItemClasses` and **`Stats`**.
  - **Protocol ID Auto-Allocation:** `DatPatchMerger` auto-computes `HASH32 = MurmurHash2-32(seed=0, UTF-8 Id)` for `BaseItemTypes`/`Words` (matching `PoeHashing.Hash32`/`PoeContentHash.MurmurHash2`) and auto-allocates collision-free unique `HASH16` values across stock + merged mods for `Mods`/`WorldAreas`/`ItemVisualIdentity`. Keep bundle header u32 offset 16 = `1` if mounting raw bundles into `fs+0xc900`, and keep `art/uiimages1.txt` BOM-less UTF-16LE CRLF.
  - **Custom Stats Design (`Stats.datc64` Closed — `#48`):** `Stats.datc64` row count **MUST stay strictly `23,362` (`0x5b42`)** — appending even 1 row collides with compiled `StatId::INVALID` (`0x5b43`) across 35+ inlined sites, triggers `"Stats enum is out of sync"` (`0x1428eed00`), and causes unchecked heap OOB writes/reads in `StatDescriptionList`, `StatValues`, `g_statInfoTable`/`g_statTopoOrder`/`g_statTopoInv`, and `StatCalc::m_hasStatBitset`. Reject any binary patch/hook lifting `0x1428eed00`; instead support custom stats via two safe, hook-free mechanisms:
